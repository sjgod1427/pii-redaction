# Deploying the web UI

The container is self-contained: it builds the spaCy model and the landing-page
showcase at image-build time and serves on port 7860, which is what Hugging Face
Spaces expects from a Docker SDK Space.

## Run it locally

```bash
docker build -t pii-redactor .
docker run --rm -p 7860:7860 pii-redactor
# open http://localhost:7860
```

Without Docker:

```bash
pip install -r requirements.txt -r requirements-web.txt
python -m spacy download en_core_web_lg
python examples/make_samples.py
uvicorn webapp.app:app --port 7860
```

**Measured on this build**

| | |
|---|---|
| Image size | 0.75 GB |
| Cold start to healthy | ~3 s (models warm in the background for ~30 s after) |
| Bundled sample, warm | ~11 s |
| Full prospectus upload, warm | ~83 s — 896 detections, 8/8 images, 0 leaks |

The `en_core_web_lg` model is 445 MB of that image. Building with
`--build-arg SPACY_MODEL=en_core_web_sm` saves roughly 430 MB and starts faster,
at a real cost in recall — the rules-only ablation in the evaluation report is
the honest floor for what you get without a good model.

## Hugging Face Spaces

The Docker SDK requires a paid account, so the Space runs on the **free Gradio
runtime**, which installs `requirements.txt` and `packages.txt` and then executes
`app.py`. That file starts the same FastAPI application `uvicorn` serves locally —
no Gradio interface is involved, the SDK is simply the free way to get a Python
process listening on port 7860.

Because there is no build step, `app.py` does what the Dockerfile did at build
time: the spaCy model is pulled in through `requirements.txt` rather than a
separate `spacy download`, and the sample documents are generated on first boot
if they are missing.

1. Create a **new Space** → SDK **Gradio** → *Blank* template → CPU basic.
2. The Space's `README.md` must begin with the YAML block already committed at
   the top of this project's README:

   ```yaml
   ---
   title: PII Redactor
   emoji: 🛡️
   colorFrom: blue
   colorTo: purple
   sdk: gradio
   app_file: app.py
   pinned: false
   ---
   ```

3. Push **the contents of this directory** as the Space root — the Space expects
   `app.py` and `README.md` at the top level, not inside `pii-redaction/`:

   ```bash
   git remote add space https://huggingface.co/spaces/<user>/<space-name>
   git subtree push --prefix=pii-redaction space main
   ```

   Authenticate with your Hugging Face username and a **write token**
   (huggingface.co/settings/tokens), not your account password.

The `Dockerfile` is kept for local use and for any host that does support Docker;
nothing on Spaces reads it.

**Hardware.** Free CPU-basic (2 vCPU) is enough. The numbers above were measured
on a laptop; expect the prospectus to take longer on a free Space. The bundled
sample and the pre-computed showcase exist so a reviewer sees the tool working
without waiting for a large upload.

**The build downloads a 445 MB model**, so the first Space build takes several
minutes. Subsequent pushes reuse the layer unless `requirements.txt` changes.

## What the Space does and does not keep

Uploaded documents routinely contain exactly the data this tool removes, so the
web layer treats them as things to get rid of quickly:

- each upload lives in a per-job temporary directory and is **never** written
  anywhere else;
- nothing is logged — not filenames, not content, not detections;
- jobs and their files are deleted after 15 minutes, and on restart;
- nothing persists between container restarts, by design.

### The sample library

Three of the four library documents are generated by `examples/make_samples.py`
and contain only invented values. The fourth is the **Red Herring Prospectus
itself**, bundled at explicit request.

> **That document embeds photographs of a real PAN card and a real Aadhaar card**
> — names, parents' names, dates of birth, national identifiers, faces and a
> signature. Because it ships in the image, anyone visiting a public deployment
> can open it from the library and read those. If that is not intended, delete
> the `prospectus` entry from `webapp/library.py` and the file from `examples/`;
> nothing else depends on it.

`mapping.json` and `detections.csv` are downloadable per job because a reviewer
needs them to audit a run — but together they are a **complete reversal key**,
and the UI says so before handing them over.
